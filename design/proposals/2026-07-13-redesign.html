Redesign Proposal

Madoi ブラッシュアップ提案

ベージュ×和のアースカラーというブランドはそのままに、面・色・タイポ・情報の並べ方を作り直す。 画面は足さない、消さない。今ある良さが見えていないだけなので、それを見えるようにする。

対象 全画面（モックはホーム / 日程調整詳細） スコープ 見た目・レイアウト・配色・コピー 対象外 ダークモード、機能変更

何が起きているか

スクリーンショットとコードを突き合わせて分かった6点。「なんとなく物足りない」の正体は、ほぼ最初の1点に集約される。

1. 平板さの正体は、カードの半透明

Card が bg-cream/88 + backdrop-blur なので、背景のグラデーションと山型イラストがカードを透けて上がってくる。 そもそもカード面 #fffaf0 と地 #f7f0e4 の明度差は4%しかなく、透過がそれを埋めて全画面が一枚のもやになる。

2. 色が働いていない

moss pine clay honey skywash mist を定義済みなのに、実際の塗りは paper / cream / ink のほぼ3色。強調は全部ただの黒ボタン。

3. 文字色が濁っている

テキスト階層を text-ink/68 のように黒の透明度で作っている。暖色のベージュ地に黒を薄く重ねると、澄まない灰色になる。暖色地には暖色グレーを重ねるのが正しい。

4. 質感に差がない

text-sm が296箇所でほぼ一色。影は1種類だけ（shadow-lift は定義されたまま未使用）。角丸は8px一律で、カードもボタンもチップも同じ手触り。フォントは未指定でOS任せ。

5. ホームの一等地が重複導線

ページ見出しの直下にクイックリンクが4枚。だが「イベント作成」はすぐ上のボタンと、「設定」はグローバルヘッダーと重複している。4枚中2枚が無価値なスペースを食い、本当に見たい「対応が必要なこと」を下へ押している。

6. 主役が埋もれている

日程調整詳細の主役は「誰が答えたか」。なのに回答状況が均等5枚サマリーの1枚でしかない。右カラムも、この画面で一番取られるアクション（リンクを配る）が3枚の中に埋もれている。

土台を作り直す

両案に共通する設計。ここが全画面に効くので、案の違いは「この上でどこまで踏み込むか」だけになる。

面 — 3段にする

canvas地#EFE7D8
surfaceカード#FFFDF7
sunken沈んだ面#F6F0E4
line境界#E4DAC6

カードは不透明にする。地を少し沈め、カードを明るくして、目に見える段差を作る。背景の山は「カードの後ろ」に正しく回る。

文字 — 暖色グレー3段

text本文 14.9:1#262320
muted補足 5.3:1#6F665C
subtle装飾のみ#948A7D

黒の透明度重ねをやめる。subtle は WCAG AA を満たさないので、罫線・プレースホルダ専用と決めてルール化する。

色 — 意味に紐づける

moss線・アイコン#5F7D65
pine強調文字・確定#344F43
clay期限・要対応#DF7D69
honey調整中#D9AA4F

値は現状のまま。使い道を決めるのが本題。moss と clay は淡い地の上だと文字として AA を割るので、文字に使うときは pine / clay-ink に落とす。

形 — リズムを付ける

cardカード14px
control入力・行10px
fullボタン・チップ999px

8px一律をやめ、この3値だけにする。影も3段（raise / soft / lift）。輪郭は罫線で出し、影は軽くする。

文字組み — Zen Kaku Gothic New

display日程調整
title候補ランキング
body◯が多く、×と未回答が少ない候補を上に並べています。
stat4/7人
caption回答受付中 / リマインド1日前

丸みのあるゴシック。「心地よく合わせる」というタグラインに合う。数字は tabular-nums で桁を揃える（日付と人数がガタつかなくなる）。 この提案書では実フォントを読み込めない（外部CDN遮断）ため、上はシステムフォントでの代用表示。

推奨は案B

ただし段階的に入れられる。案Aの土台（トークン・プリミティブ）を先に入れて全画面を底上げし、そのあとホームと日程調整詳細だけ案Bの情報設計に進む、という順序を勧める。

なぜ案Bか

  • 案Aだけだと、重複導線が残る。 見た目は締まるが、ホームの一等地をクイックリンク4枚（うち2枚は重複）が占め続ける。この構造的な問題は、色や影では直せない。
  • 0件のチップを6個並べるのをやめる。 「すべて0 / 期限0 / 未回答0…」は情報量がゼロなうえ、空っぽ感を増幅している。件数があるものだけ出す。
  • 回答状況を主役にすると、次の行動が決まる。 「4/7人・あと3人・期限は明日」まで一目で読めれば、ユーザーがやることは「リマインドを送る」に自ずと決まる。だから右カラムも「リンクを配る」を主役に格上げした。
  • 色が意味を持つ。 clay = 期限、honey = 調整中、moss/pine = 確定。今は定義されているだけで一度も使われていない色が、ここで初めて働きはじめる。

案Bのリスク

  • 変更範囲が広い。 ホームと日程調整詳細のコンポーネントを組み替えるので、案Aより差分が大きく、レビューも重くなる。
  • ヘッダー直下のテキストナビは新しい要素。 ただし docs/design/03_screen_flow.md の「常時表示の左メニューや下部タブは置かない」という方針には抵触しない範囲に収めている（サイドバーでも下部タブでもない）。ここは判断がほしい。
  • 挨拶コピーは好みが分かれる。 「こんにちは、◯◯さん」が合わないなら「ホーム」のままでいい。トークンとレイアウトの話とは独立している。

状態とエッジケース

モックは「ちょうどよくデータがある」状態しか描いていない。実装では以下を決めておく必要がある。

場面 状態 扱い
対応が必要なこと 0件 チップ行そのものを出さない。カードは残し、「いま対応が必要なものはありません。」＋チェックアイコンの空状態。現状は0件チップを6個並べていて、空虚さを増幅している。
件数が多い 期限が近い順に最大5件。以降は「通知を開く」へ送る。
回答状況 参加者0人 進捗バーを出さず、「まだ誰も招待していません」＋共有リンクへの導線に切り替える。0/0人 で 0% のバーを出すと、壊れて見える。
全員回答済み バーを moss で満たし、バッジを「確定できます」に。CTA「日程を確定」を主ボタンとして強調。
期限バッジ 24時間以内 / 超過 clay（期限が近い）／ 超過時は「受付終了」の neutral に落とす。超過後も赤いままだと、直しようのない警告を出し続けることになる。
候補ランキング 同スコアが並ぶ 「おすすめ」バッジは最上位1件のみ。同点なら日付が早い方。2件に付けると推薦の意味が消える。
未回答者 0人 カードを縮小し、「全員から回答が届いています。」の1行に。空カードで縦を食わない。
共有リンク 日程確定後 「いま一番効くこと」の見出しを外し、通常カードに降格。確定後にリンク配布を煽る意味はない。
subtle 色 常時 WCAG AA（4.5:1）を満たさないため、本文・ラベルには使わない。罫線・プレースホルダ・装飾のみ。ルールとして design/rules.md に固定する。

進め方

実装は4段階。1と2を入れた時点で全画面が底上げされるので、そこで一度スクリーンショットを撮って確かめられる。

1. 土台

tailwind.config.ts にトークン、app/layout.tsx に Zen Kaku Gothic New、app/globals.css の背景装飾を調整。design/tokens.css と design/rules.md も同時に作る。

2. プリミティブ

components/ui.tsx の Card / EmptyState / PageHeader を直し、Badge Stat Alert Progress を足す。Card を直した時点で全画面に効く。

3. 情報設計（案B）

ホームのクイックリンク撤去と「対応が必要なこと」の繰り上げ、日程調整詳細の主役立て。ここだけレイアウトに触る。

4. 横展開と検証

清算ページ（rounded-* が36箇所と最も散らかっている）などのアドホックな記述をプリミティブへ回収。Playwright で全画面のビフォー / アフターを撮り、コントラスト比も確認する。

モックは実装予定のトークンで組んでいる。フォントだけは、この提案書が外部CDNを読み込めないためシステムフォントで代用している（実装では Zen Kaku Gothic New）。
