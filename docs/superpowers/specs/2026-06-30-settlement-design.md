# Phase 3-A Settlement Design

## Goal

Madoiの参加予定に、支払い履歴と清算結果を追加する。日程調整の後に、誰が誰へいくら払うかを迷わず確認できる状態にする。

## Scope

- 支払い履歴を追加する
- 支払った人を選ぶ
- 負担者を選ぶ
- 均等割りで負担額を作る
- 個別金額で負担額を作る
- 清算結果を自動計算する
- 支払い済みと受け取り確認を記録する
- 支払い方法メモと支払い用URLを保存する
- 清算リマインド文面をコピーし、送信済みを記録する

## Out Of Scope

- 外部決済APIとの直接連携
- 支払い証拠画像アップロード
- LINE、Discord、メールなどへの自動送信
- 支払い済み清算がある状態での費用再計算

## Data Model

- `expenses`: 支払い履歴
- `expense_splits`: 各支払いの負担額
- `settlements`: 相殺後の清算結果
- `payment_proofs`: 支払い済み登録時のメモまたはURL
- `settlement_reminder_logs`: 清算リマインドの送信済み記録

## Calculation Rule

参加者ごとに `paid_total - owed_total` を計算する。プラスの人を受け取り側、マイナスの人を支払い側にして、参加者順で相殺する。

均等割りの端数は、参加者順に1円ずつ前から配る。個別金額は合計が支払い金額と一致しない場合は保存しない。

## Safety

支払い済みまたは受け取り確認済みの清算がある場合、費用追加はブロックする。Phase 3-Aでは、清算開始後の再計算によるズレを避ける。
