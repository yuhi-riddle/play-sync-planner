# つながり画面に「進行中の共通イベント」を出す（案A）

- 日付: 2026-09-16
- ステータス: 設計中（ユーザーレビュー待ち）
- 関連: gpt-6-astraによる事前レビュー（つながり機能拡充のアイデア出し、本セッション内）

## 背景

「つながり」画面（`app/connections`）は相手ごとに「共通のイベント◯件」という**件数**しか出さない。過去のイベントも含めた累計で、今どのイベントが動いているかは分からない。

ユーザーの元アイデア: 「同じメンバーで複数のイベント/日程調整が並行して進んでいることがある。それをまとめて見えるようにしたい」。gpt-6-astraによる事前レビューで比較した3案（①軽い横断表示／②常設グループ／③複数人で絞る保存ビュー）のうち、①を採用する。②③は今回のスコープ外（将来、必要になったら別途検討）。

## ゴール

つながり画面の人物行から、その相手と自分が今も一緒に参加している進行中のイベント一覧を確認できるようにする。

## スコープ

**含む**: つながり画面（`app/connections`, `components/account/connection-list.tsx`）の人物行への導線、進行中共通イベントの一覧モーダル、それを支えるDB migration（列追加＋新RPC）

**含まない**: イベント詳細画面側からの導線、常設「グループ」概念、複数人（3人以上）で絞り込むビュー

## 対象・範囲

- 表示場所: つながり画面の人物行のみ。フォロー中／お気に入り／相互フォロー／共有（＝共通イベントあり）の4タブが対象。**ブロック中タブには出さない**
- 「進行中」の定義: 既存の一覧フィルタ `matchesEventListFilter("active")`（`lib/domain/event/event-filter.ts`）と同じ。`status ∈ {interested, planning, confirmed}` に加え、開催済みでも精算が済んでいない場合（`settlement_waiting`）も含む
- 「共通」の定義: 自分と相手の両方が、そのイベントに `event_members.status = 'joined'` で**現在も**参加している（過去に参加していて抜けた場合は対象外）

## データ取得

### 列追加（既存RPC）

`list_connections` が返す各行に `active_shared_event_count` を追加する。算出方法は既存の `shared_memberships` CTE（`supabase/migrations/034_connection_calendar_rpc.sql`）に、イベント側の進行中条件を足すだけ。既存の `shared_event_count`（累計）とは別の列として持つ。

### 新規RPC: `list_active_shared_events(p_other_user_id uuid)`

モーダルを開いたときに1回だけ呼ぶ。戻り値: `event_id`, `title`, `display_state`（`participant_waiting` 等の派生状態そのもの）。行ごとの事前取得はしない（一覧表示時にN+1にならないよう、件数だけ`list_connections`側に持たせ、詳細はオンデマンド取得にする）。

自分から見えないイベント（ブロックされている等）は対象外。ブロック中の相手はそもそも人物行にボタンを出さないので、このRPCがブロック相手に対して呼ばれることはない想定だが、RPC自体にも自分と相手の双方向ブロックチェックを入れる（直接叩かれた場合の保険）。

### migration

新しいmigrationファイル1本（列追加＋新RPC定義）。**DBスキーマ変更にあたるため、実装前に内容を確認してもらってから適用する**（既存の運用ルール通り）。

## UI

### 人物行（`ConnectionRow`, `components/account/connection-list.tsx`）

既存の「共通のイベント◯件」の下に、`activeSharedEventCount > 0` のときだけボタンを追加:

```
共通のイベント 5件
[進行中 2件]  ← これを新設
```

ボタン押下でモーダルを開く。

### モーダル（新規コンポーネント）

`components/legal/legal-modal.tsx` と同じ自前実装パターン（フォーカストラップ・Escapeで閉じる・`aria-labelledby`）を踏襲する。共通の`Modal`抽象は作らない（このプロジェクトに既存の汎用モーダルコンポーネントは無く、各画面で個別実装する流儀のため）。

中身: イベント名＋現在の状態ラベル（`eventDisplayStateLabels`を流用、例: 「参加者待ち」「開催待ち」）の行リスト。各行はイベント詳細ページへのリンク。0件（開いた瞬間に相手が抜けた等の競合）はそのまま空表示。

## エッジケース

| 状況 | 挙動 |
|---|---|
| モーダルを開いた後、相手がイベントを抜けた | 反映されない（開いた時点のスナップショット）。閉じて再度開けば最新になる |
| 相手をブロックする直前にモーダルを開いていた | 既存のブロック処理のみ実行。モーダル自体は自動で閉じない（他の操作と同様、画面更新は既存の`ConnectionList`の再同期に委ねる） |
| 進行中の共通イベントが0件 | ボタン自体を出さない（「共通のイベント◯件」の行はそのまま） |
