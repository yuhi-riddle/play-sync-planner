# ホーム画面リデザイン(全画面リデザインの第1弾)

作成: 2026-08-17

## 背景

「ミヤマグラフィックス」のスタイルガイド(生成り×濃い緑×パステル差し色×丸っこいカード)を参考に、Madoi 全画面のデザインシステムを刷新するプロジェクトの最初のサブプロジェクト。

現行デザイン(`design/tokens.css` / `design/rules.md`)は面3段・角丸14px/10px・黒(ink)を主CTA色に使う設計だが、新方針では黒をテキストのみに後退させ、CTAは緑(pine)に統一する。全画面を一度に変更すると影響範囲が大きすぎるため、まずホーム画面だけをスコープにし、ここで固めたトークン刷新をベースに、イベント一覧・カレンダー・つながり等は後続の別 spec で展開する。

ホーム画面の情報設計は、ブレインストーミングで以下の順に検討・決定した。

1. 既存の4枚クイックリンクカード撤去(`design/rules.md` の「グローバルヘッダーやページCTAと同じ導線をページ本文にもう一度置かない」ルールに抵触するため)→ 現状の `app/page.tsx` には既にクイックリンクは無く、この項目は達成済み
2. 挨拶文・大きなCTA・「対応が必要なこと」「次の予定」の構成に着地
3. ユーザーレビューで「今日の予定」「一緒に参加」の2 stat は情報として弱いと判断し削除
4. 同じレビューで「あっさりしすぎ」の指摘を受け、既存機能である `HomeSelectedDateAgenda`(選択日の予定)をビジュアル刷新のうえフル復活

Artifact でモバイル実寸モックアップを作成し、上記の意思決定はすべてユーザー確認済み(最終形: https://claude.ai/code/artifact/55c56b74-9360-4525-9a2f-e509ec80ac3c )。

## デザイン方針(トークン刷新)

`design/tokens.css` が正本、`tailwind.config.ts` はミラーという既存ルールは維持し、**両方同時更新**する。

| トークン | 現行 | 変更後 | 理由 |
|---|---|---|---|
| `--madoi-canvas` | `#efe7d8` | `#f7f3ef` | より明るい生成りへ。参考画像に合わせる |
| `--madoi-radius-card` | `14px` | `20px` | 丸みを拡大 |
| `--madoi-radius-control` | `10px` | `14px` | 同上 |
| CTA背景 | `ink`(黒) | `pine` ベースのグラデーション(`#3a5c4c → #2c4638`) | 黒はテキストのみに後退。ブランドの主張は緑で行う |

`surface` / `sunken` / `line` / `line-strong` / 暖色グレー3段 / `moss` `clay` `honey` `skywash` `mist` の値と用途対応は変更しない。`design/rules.md` の「色の意味」表と禁止パターン(半透明面禁止、`text-subtle` を本文に使わない、等)はそのまま踏襲する。パステル差し色(honey/clay/skywash、新規カテゴリ色は別 spec で検討)はカテゴリ・ステータス表示に限定し、全面パステル化はしない。

**フォント**: `next/font/google` で Zen Maru Gothic を導入。`subsets: ['japanese']` 必須、`weight: ['400','700']`、`display: 'swap'`。2026-07-13 に撤去した `Zen Kaku Gothic New` は `subsets: ['latin']` のみ指定した設定ミスで日本語グリフを一つも含んでいなかった(256KB が無意味に読み込まれていた)失敗があるため、`japanese` サブセット指定を実装後に必ず目視確認する。

**ロゴ**: `app/layout.tsx:50-56` の現行実装は `clip-path: polygon(...)` を4枚重ねた幾何学的三角形。これを、参考画像に沿った「山＋太陽」のイラスト表現に置き換える。**今回のスコープでは線画・単純な塗りレベルのSVGコンポーネント化までとし、写実的な質感の作り込みは別タスクとする**(インラインCSSのままだと保守性が低いため、`components/` 配下に独立した Logo コンポーネントとして切り出す)。

## ホーム画面の構成(変更後)

`app/page.tsx` を上から並べ替え、以下の構成にする。

1. **ヘッダー**(`app/layout.tsx`) — ロゴ＋アプリ名、通知ベル(未読バッジ)、アバター(イニシャル表示)。既存の `AuthNav` を流用しつつアイコンとロゴのみ差し替え。
2. **挨拶** — 「こんにちは、〇〇さん」を独立した見出し(`text-display` 相当)にする。現行は `PageHeader` の `description` に埋め込まれているが、`greetingTitle()` の呼び出し位置を変更し、見出しとサブテキストの2段に分離する。
3. **CTA**(イベント作成) — 現行はヘッダー内 `action`(デスクトップのみ表示)に留まっている小さいボタン。本文側にサブテキスト付きの大きなカードとして配置し、デスクトップ・モバイル問わず常に表示する。既存の `MobileEventFab` は維持する。本文CTAは「ホームを開いた直後に押す」動線、FABは「下にスクロールした後でも手元にある」動線として役割を分担する(同一ページに導線が2つになるが、`design/rules.md` の禁止パターンはヘッダーとページ本文の重複を指しており、本文内とFABの重複は対象外)。
4. **「対応が必要なこと」プレビューカード**(新規) — 件数バッジ＋最も優先度の高い通知1件のタイトルを1行で表示する幅いっぱいのカードにする。タップで `/notifications` に遷移。現行の `filteredNotifications` 一覧・フィルターチップ表示はホームから撤去し、`/notifications` に一本化する。
   - 優先順位: `payment_due` / `answer_deadline` を最優先 → `settlement_needed` / `confirmation_due` → `unanswered` / `answer_received`。同順位内は現行同様「新しいものから」。
   - 0件時はカード自体を非表示(`design/rules.md` の「0件のフィルタチップを並べない」と同じ思想)。
5. **「次の予定」カード** — `components/home/home-next-confirmed-event-card.tsx` はロジック変更なし。角丸・余白などビジュアルのみ新トークンに追従。
6. **「選択日の予定」** — `components/home/home-selected-date-agenda.tsx` はロジック変更なし(今日/明日/週末ショートカット、週間グリッド、Madoi予定＋Googleカレンダーのアジェンダ一覧)。ビジュアルを新トークンに刷新し、`SectionHeading` の `action` にあった Google 連携ステータステキストはそのまま維持する。
7. **独立していた「Googleカレンダーと連携しよう」案内カードは削除** — 手順6のステータステキストと役割が重複するため。
8. **下部4タブナビ**(`components/layout/primary-nav.tsx`) — 構成(ホーム/イベント/カレンダー/つながり)は変更なし。アイコンは既存どおり lucide-react を使用し、角丸・カラーのみ新トークンに追従。

### 対象ファイル

- `design/tokens.css` / `tailwind.config.ts` — 色・角丸トークン更新(同時更新必須)
- `design/rules.md` — 角丸値の記述更新、CTA配色ルール(ink→pine)の追記
- `app/layout.tsx` — ロゴコンポーネント差し替え、Zen Maru Gothic 導入
- `app/page.tsx` — セクション構成の並べ替え、対応が必要なことプレビューカードの実装、優先順位ロジックの追加
- `components/home/home-selected-date-agenda.tsx` / `home-next-confirmed-event-card.tsx` — ビジュアル刷新(ロジック変更なし)
- 新規: `components/layout/logo.tsx`(仮) — ロゴのコンポーネント化
- 新規: `components/home/home-priority-notification-card.tsx`(仮) — 対応が必要なことプレビューカード

## 検証方法

- `npm run dev` でホーム画面を実データ・実操作で確認する。特に以下の状態を個別に確認:
  - 通知が 0件 / 1件 / 複数件(優先順位が正しいものが表示されるか)
  - 次の予定が無い場合(カードごと非表示になるか、現行ロジック通り)
  - Google カレンダー 連携済み / 未連携
- モバイル幅(375px)とデスクトップ幅の両方で崩れがないか確認
- 既存のホーム関連テスト(Vitest、`--reporter=dot`)を実行し、レイアウト変更に伴う破壊がないか確認。優先順位ロジックなど新規ロジックにはテストを追加する
- アクセシビリティ: タップ領域44px以上、フォーカスリング、`Zen Maru Gothic` 適用後のコントラスト比が既存の暖色グレー3段の基準(本文4.5:1以上)を保っているか
