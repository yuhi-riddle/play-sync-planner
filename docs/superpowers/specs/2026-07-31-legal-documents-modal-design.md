# Madoi 規約・プライバシーポリシーのモーダル表示 設計

日付: 2026-07-31  
ステータス: 承認済み

## 目的

ログイン画面の同意欄から利用規約・プライバシーポリシーを読むとき、別ページへ遷移していたのをやめ、その場でモーダルに出す。読んで戻る往復が消え、往復のあいだ状態を保つための `sessionStorage` も不要になる。

## 対象

- ログイン画面の同意欄（`components/login-consent-form.tsx`）にある「利用規約を読む」「プライバシーポリシーを読む」の2つ

## 対象外

- フッター（`app/layout.tsx`）のリンクは画面遷移のまま。全ページに出るため、モーダル用のクライアントコードを全ページへ積むことになるのを避ける
- `/terms` `/privacy` のページ自体は**残す**。直リンクと検索から辿れる必要があるため

## 画面

中央に出るカード。既存の確認ダイアログ（`components/confirm-form.tsx`）と同じ見た目のパターンを使い、画面内の一貫性を保つ。

- 上部に表題（「利用規約」「プライバシーポリシー」）と閉じるボタン
- 本文が入りきらない場合はモーダルの内側でスクロールする
- 下部にも閉じるボタンを置く（読み終わった位置から閉じられるように）

## キーボードと支援技術

- `role="dialog"`、`aria-modal="true"`、`aria-labelledby` で表題と結びつける
- Escape キーで閉じる
- 開いたら閉じるボタンへフォーカスを移す
- 閉じたら、開くきっかけになったボタンへフォーカスを戻す
- Tab がモーダルの内側を循環する。操作できる要素は閉じるボタンだけなので、簡易な実装で足りる

## 同意フローへの影響

- 「読む」リンク（`<Link>`）は、モーダルを開くボタン（`<button>`）に変わる
- モーダルを開いた時点で、これまでと同じくチェックボックスが有効になる。「開いた＝読める状態にした」という担保の強さは現状と変わらない
- 画面遷移が無くなるため、`sessionStorage`（キー `madoi-login-consent`）による下書きの保存・復元を**削除する**。同じ画面に留まるので React の state だけで足りる
- `/terms` `/privacy` が受け取っている `from` / `next` クエリは残す。ログインからの遷移は無くなるが、直リンクで開いた場合の戻り先として機能し続ける

## 本文の持ち方

現在、本文は各ページの中に `{ title, body }` の配列として直接書かれている。これをページとモーダルの両方から使えるように切り出す。

- `lib/legal-documents.ts` — 利用規約・プライバシーポリシーの本文と施行日
- `components/legal-document-body.tsx` — 本文を描画する共有コンポーネント。ページとモーダルの両方が使う

## テスト

- モーダルが開くこと、Escape で閉じること、閉じたときにフォーカスが開いたボタンへ戻ること
- モーダルを開くとチェックボックスが有効になること
- `/terms` `/privacy` のページ表示が変わらないこと（節の見出しと本文が従来どおり出る）
- 同意フォームが `sessionStorage` を使わなくなったこと

## 今回やらないこと

- フッターのリンクのモーダル化
- 「最後までスクロールしないと同意できない」といった制約の追加
