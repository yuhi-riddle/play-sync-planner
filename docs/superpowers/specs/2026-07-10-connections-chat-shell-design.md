# つながり・イベントチャット・画面シェル設計

## 目的

Madoi で一度同じイベントに参加した人を、次回の招待で素早く選べるようにする。
あわせて、イベント参加者だけで連絡できるチャットを用意する。

投稿型SNSにはせず、日程調整とイベント運営を軽くするための機能に限定する。

## 方針

### つながり

- 関係は一方向のフォローとする
- フォロー候補には、過去または現在の同一イベントに参加したユーザーだけを出す
- 相互フォローは表示するが、承認フローは設けない
- 招待候補では、相互フォローの人を最優先にし、片方向フォローの人をその次に表示する
- 検索、公開プロフィール、投稿、活動履歴の公開は実装しない
- 片方向フォローでもDMを開始できるようにする
- フォローされた側が相手を知らない場合でも、ブロックすれば以後のフォロー、DM、候補表示を止められる
- フォロー中の相手は自分用にお気に入り登録できる
- お気に入りは相手に通知せず、招待候補の最上位に表示する
- お気に入り、フォロー中、最近同じイベントにいた人には、Madoi内の招待通知を送れる

### イベントチャット

- チャットはイベントごとに1つだけ持つ
- イベント参加中のユーザーだけが閲覧と投稿をできる
- メッセージは本文、送信者、送信日時のみを保存する
- 編集、削除、リアクション、画像添付、既読表示、DMは今回の対象外
- 新着はサイト内通知で案内する。リアルタイム同期は後続対応とし、初回は画面再読み込みで更新する

### Calendarの空き状況

- Google Calendar連携は自分の予定表示と確定予定の登録に使う
- 他参加者の空き状況を集計できるのは、日程調整が回答受付中の間だけにする
- 集計は主催者だけに表示し、参加者は自分のCalendarだけを見ながら回答する
- 集計結果は保存せず、予定名、場所、個人ごとの空き時間は返さない
- 日程を確定または中止した時点で、他参加者の空き状況を再取得するAPIを停止する
- 確定後に日程を変える場合は、主催者が再調整を明示的に開始する。そのときだけ最新の空き状況を再取得し、参加者へ再回答を依頼する

### 画面シェル

- 上部ヘッダーはスクロール中も固定する
- 通知、設定、ログアウトは固定ヘッダー内に置く
- イベント作成はモバイルで右下のFABを表示する
- デスクトップでは既存のページ見出しの作成ボタンを維持し、FABは表示しない
- FABはホーム、イベント一覧、調整カレンダーで表示する。作成中・編集画面・規約画面では表示しない

### 利用規約・プライバシーポリシー

- 他サービスで一般的な見出し構成に寄せるが、文章はMadoi向けに書き直す
- 利用規約は、適用、アカウント、利用者の責任、禁止事項、サービス変更、免責、規約変更、連絡先で構成する
- プライバシーポリシーは、取得情報、利用目的、Googleの情報、共有範囲、外部委託先、安全管理、保存期間、問い合わせで構成する
- 実際に行っていない処理、公開DM、投稿、広告利用などは記載しない
- 公開前に、運営者名、所在地、問い合わせ先、公開日を確定して差し替える

## データ設計

### user_connections

| カラム | 内容 |
|---|---|
| follower_user_id | フォローするユーザー |
| followed_user_id | フォローされるユーザー |
| created_at | フォロー日時 |

- `follower_user_id` と `followed_user_id` を一意にする
- 自分自身をフォローできない制約を付ける
- RLSで、自分のフォロー作成・解除と、自分が関係するフォローの閲覧だけを許可する
- フォロー作成時は、両者が同じイベントの参加者であることをサーバー側で検証する

### user_blocks

| カラム | 内容 |
|---|---|
| blocker_user_id | ブロックするユーザー |
| blocked_user_id | ブロックされるユーザー |
| created_at | ブロック日時 |

- `blocker_user_id` と `blocked_user_id` を一意にする
- 自分自身をブロックできない制約を付ける
- ブロックすると、両方向のフォローを解除する
- ブロック関係がある二人の間では、将来のDM開始、フォロー作成、招待候補表示を禁止する

### user_favorites

| カラム | 内容 |
|---|---|
| user_id | お気に入り登録するユーザー |
| favorite_user_id | お気に入りにするフォロー相手 |
| created_at | 登録日時 |

- `user_id` と `favorite_user_id` を一意にする
- お気に入りにできるのは、自分がフォローしている相手だけとする
- お気に入り登録は完全に自分用で、相手への通知や公開はしない

### event_user_invitations

| カラム | 内容 |
|---|---|
| id | 招待ID |
| event_id | 招待するイベント |
| inviter_user_id | 招待した主催者 |
| invitee_user_id | 招待されたユーザー |
| status | pending / accepted / declined / revoked |
| created_at | 招待日時 |
| responded_at | 回答日時 |

- `event_id` と `invitee_user_id` の組み合わせで、招待中の重複を作らない
- 主催者だけが招待を作成・取り消しできる
- 招待されたユーザーは承認または辞退だけを行える
- 承認時にイベント参加者を作成し、必要ならGoogle Calendar連携へ案内する
- Madoi内招待は過去または現在の同一イベント参加者に限定する
- 既存の共有リンクは、Madoiを使っていない人へ外部から招待するために残す

### event_messages

| カラム | 内容 |
|---|---|
| id | メッセージID |
| event_id | 対象イベント |
| author_user_id | 投稿者 |
| body | 本文 |
| created_at | 投稿日時 |

- 本文は空白のみを禁止し、最大2,000文字にする
- RLSで、参加中のイベントに対する閲覧・投稿だけを許可する
- 主催者でも他者の投稿を編集・削除できない

## 画面と導線

### イベント詳細

- 参加者カードに、表示名とフォロー状態を出す
- 自分以外の参加者にはフォロー・フォロー解除を表示する
- 「チャット」セクションを日程調整の後ろに追加する
- 参加者はイベント内容を編集できないが、チャット投稿とフォローはできる
- 主催者には、つながりから相手を選んでMadoi内招待を送る画面を表示する

### つながり画面

- 設定から開く
- お気に入り、相互フォロー、フォロー中、同じイベントにいたフォロー候補を分けて表示する
- 相手ごとにお気に入り、フォロー解除、ブロックを選べる
- 招待候補のための画面であり、プロフィール詳細や投稿一覧へは遷移させない

### イベント作成

- ホームとイベント一覧では、モバイル幅だけFABを表示する
- FABは `イベントを作る` に直接遷移する

## 通知

- フォロー・お気に入り登録は通知しない
- Madoi内招待は、招待された本人へサイト内通知を作成する
- イベントメッセージは、投稿者以外の参加者にサイト内通知を作る
- 同じイベントで未読のチャット通知が増えすぎないよう、イベントと受信者単位で通知をまとめる

## エラーと権限

- 参加者でないイベントのチャット画面は404相当として扱う
- フォロー対象が同一イベントの参加者でない場合は、操作を拒否する
- ブロック関係がある相手へのフォロー、DM、候補表示を拒否する
- ブロック関係がある相手へのMadoi内招待を拒否する
- 確定・中止済みの日程調整では、他参加者のCalendar空き状況を集計しない
- 中止済みイベントのチャットは閲覧のみとし、新規投稿を受け付けない
- フォロー操作、チャット送信の失敗はMadoiのインラインエラーで表示する

## テスト

- 同一イベント参加者だけをフォロー候補にできること
- 自己フォローと重複フォローを拒否すること
- 相互フォロー判定が正しいこと
- ブロックにより両方向のフォローが解除され、以後の接触が拒否されること
- お気に入りが招待候補の最上位に表示され、相手には見えないこと
- Madoi内招待が通知として届き、承認時にイベント参加者になること
- イベント参加者だけがメッセージを閲覧・投稿できること
- 空白のみ、2,000文字超の投稿を拒否すること
- モバイルだけFABが出ること
- ヘッダー固定時にメイン内容が隠れないこと

## 実装順

1. 利用規約・プライバシーポリシーの文面と導線を改稿する
2. 固定ヘッダーとモバイルFABを追加する
3. `user_connections`、`user_blocks`、`user_favorites` とつながり画面を追加する
4. 招待候補へお気に入り、フォロー、最近の参加者の順で優先表示を組み込み、Madoi内招待を送れるようにする
5. Calendar空き状況APIを日程調整中だけに制限し、再調整フローを追加する
6. `event_messages`、イベント詳細のチャット、通知を追加する
7. RLS、Server Actions、テスト、モバイル表示を確認する
