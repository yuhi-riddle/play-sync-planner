# モバイル表示の改善

作成: 2026-08-03

## 背景

375px の実機で操作したところ、見にくい・操作しにくい箇所が複数見つかった。
すべてユーザーが撮影したスクリーンショットに写っており、原因はコード上で特定済み。

進行表（[2026-08-03-plan-timetable-design.md](2026-08-03-plan-timetable-design.md)）も
同じモバイル画面の上に乗るため、**土台であるこちらを先に直す**。

## 方針

既存の視覚言語（暖色の紙 canvas `#efe7d8` / surface `#fffdf7`、丸ピル、控えめな苔緑 moss `#5f7d65`、
影は最小限）は変えない。**新しい色・部品・パターンを足さない。**

判断基準は「1画面に何が見えるか」。装飾ではなく占有面積を削る。

### 共通原則

1. **空の情報は出さない。**「未設定」を並べるより、確定した情報だけ見せる
2. **縮まない要素（select・button）を縮む要素と横並びにしない。** 混ぜるなら縮む側を独立行にする
3. **固定要素（ヘッダー・ボトムナビ・FAB）の占有分は、コンテナの padding で必ず確保する**

## 直す対象

### 1. ヘッダーがモバイルで2段になる

**現状** — [app/layout.tsx:47](../../../app/layout.tsx) がモバイルで `flex-col gap-3`。
ロゴ行と `AuthNav` 行が縦に積まれる。`AuthNav` は
[components/auth-nav.tsx:45](../../../components/auth-nav.tsx) の
`grid-cols-[minmax(0,1fr)_repeat(2,2.75rem)]` でユーザー名ピルが横幅いっぱいを取る。
`sticky top-0` なので常時居座り、約104px を消費する。

**直し方** — モバイルでも1段にする。

- ロゴマークを縮める
- ユーザー名ピルを**アバターのみのアイコンボタン**にする（名前は `aria-label` と `title` に残す）
- 通知ベル・ログアウトは現状のアイコンサイズを維持する

**確認** — ヘッダー高さが概ね半分になり、最初のカードがファーストビューに入ること。

### 2. イベント一覧カードが「未設定」で行を浪費する

**現状** — [app/events/page.tsx:204](../../../app/events/page.tsx) の `grid gap-2` は
モバイルで1列。日程・場所・参加人数が縦に3行並ぶ。値が「日程未設定」「場所未設定」でも
3行分の高さを使う。

**直し方**

- **日程・場所は未設定なら行ごと出さない**
- 参加人数は常に出す（0人でも意味があるため）
- 表示するものが複数あるときは横1行に並べ、入りきらなければ折り返す

**注意** — `formatSchedule` が返す「日程未設定」と、`location_name` の
`|| "場所未設定"` フォールバックが対象。**文言を変えるのではなく、出さない。**

### 3. FAB が最後のカードに重なる

**現状** — [components/mobile-event-fab.tsx:28](../../../components/mobile-event-fab.tsx) は
`bottom-[calc(5.5rem+env(safe-area-inset-bottom))]`。FAB 自体の高さ（約3rem）を足すと
8.5rem 必要だが、[app/layout.tsx:61](../../../app/layout.tsx) のコンテナは `pb-28`（7rem）しかない。

**直し方** — FAB が出る画面幅（`sm` 未満）で下パディングを 9rem 相当まで広げる。
`sm:` 以上は現状維持（FAB は `sm:hidden`）。

**注意** — フッターにも `pb-28` があるので揃える。

### 4. タスク行のタイトルが1文字幅まで潰れる

**現状** — [components/event-task-list.tsx:97](../../../components/event-task-list.tsx) が
`flex flex-wrap items-center gap-3` の1行に、チェック・タイトル・担当セレクト・削除を並べている。
タイトルは [L115](../../../components/event-task-list.tsx) で `min-w-0 flex-1 break-words` なので、
縮まないセレクトに押されて1文字幅まで縮む。

**直し方** — モバイルではタイトルを独立行にする。

- 1行目: チェックボタン ＋ タイトル
- 2行目: 担当セレクト ＋ 削除（タイトルの字下げに揃える）
- `sm:` 以上は現在の1行レイアウトを維持してよい

### 5. チャットの投稿ボタンが画面外に出る

**現状** — [components/event-chat.tsx:74](../../../components/event-chat.tsx) の
`rows={4}` で入力欄が高く、その下の「2,000文字まで」と投稿ボタンが折り返し位置より下に出る。
ソフトキーボードが出れば確実に隠れる。

**直し方**

- `rows={2}` にする
- 文字数の注記は常時表示をやめる。**残り文字数が少なくなったときだけ出す**か、
  入力が始まってから出す
- 投稿ボタンは右寄せのまま維持する

## ついでに直す不具合

表示の問題ではないが、同じ実機確認で見つかったもの。小さいのでここに含める。

### 6. 中止イベントに「日程調整を始める」が出る

[app/events/[eventId]/page.tsx:115](../../../app/events/[eventId]/page.tsx) の
`canStartAdjustment` が招待の締め切り状態しか見ておらず、`event.status === "cancelled"` を
判定していない。中止イベントでもボタンが出る。

同じ変数が [L158](../../../app/events/[eventId]/page.tsx) の説明文と
[L215](../../../app/events/[eventId]/page.tsx) の「日程調整の準備中」にも使われているので、
3箇所すべてに効く。

### 7. `notFound()` がクエリエラーを飲み込む

[app/plans/[planId]/settlement/page.tsx:144](../../../app/plans/[planId]/settlement/page.tsx) が
`const { data: plan }` とだけ書き、`error` を捨てている。
その結果、**クエリの失敗がすべて404として表示される**。

実際にこれで遠回りした。マイグレーション 025 未適用により
`participants.settlement_payment_method` が存在せず、PostgREST が 42703 を返していたが、
画面には「ページが見つかりません」としか出なかった。

**直し方** — `error` を受け取り、行が無い場合（本当の404）と
クエリが失敗した場合（サーバーエラー）を区別する。後者は `error.tsx` に投げる。

**注意** — 同じ書き方が他のページにもある可能性がある。実装時に横展開して確認する。

## スコープ外

- 追加UIの作法統一（`<details>` 化）— 進行表で先に実装し、その後まとめて展開する
- 立替フォームの専用ページ化
- `event_tasks` の複数担当化
- 受け取り方法の複数指定
- デスクトップ表示の調整（今回はモバイルのみ）

## テスト方針

- jsdom は computed style を取れないので、**クラス名の検証**が作法
- 「未設定なら出さない」は**負のアサーション**で固定する（未設定の文言が DOM に存在しないこと）
- `canStartAdjustment` は中止イベントでボタン・説明文・準備中表示のいずれも出ないことを検証する
- `notFound()` の分岐は、クエリ失敗時に404ではなくエラーが投げられることを検証する
- 既存テストのうち、レイアウト変更で壊れるものを洗い出して更新する
  （`tests/route-loading-skeletons.test.tsx` ほか）

## 実機での確認観点

- ヘッダーが1段になり、最初のカードがファーストビューに入る
- イベント一覧で FAB が最後のカードに重ならない
- タスク名が潰れずに読める
- チャットで入力してから投稿ボタンまでスクロールが要らない
- **iOS と Android の両方**で、キーボードが出たときに入力欄が隠れない
  （iOS はキーボードを重ね、Android はレイアウトをリサイズするため挙動が違う）
