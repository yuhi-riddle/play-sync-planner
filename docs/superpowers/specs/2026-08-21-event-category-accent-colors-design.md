# イベントカテゴリの差し色(全画面リデザイン展開・第1弾)

作成: 2026-08-21

## 背景

ホーム画面リデザイン(`2026-08-17-home-redesign-design.md`)で確定したトークン・パターンを他画面へ展開する作業の一環。イベント一覧が「一目で何の予定か分かる」状態になっていない(現状、実カードにはカテゴリ表示自体が無い)ことが出発点。

ブレインストーミングで以下を検討・決定した。

1. 差し色をどこに使うか — Artifact で4案(一覧カード / 絞り込みチップ / 詳細ヘッダー / カレンダー)を比較(https://claude.ai/code/artifact/587d8f17-f7f3-4bba-af77-41969d99b349 )。**一覧カードが最有力**と判断: 現状カテゴリ表示が無い箇所への追加で実装コストが最小、かつ最も閲覧頻度が高い画面。他3箇所は今回スコープ外(反応を見てから検討)
2. カテゴリの粒度そのものの見直し(自由入力化)を検討したが、具体的に既存8カテゴリで表現できない実例が無く、自由入力にすると「カテゴリごとに固定色」という前提が崩れる(DB側もenumから自由テキストへ、フィルターUIもドロップダウンから検索式に変わる規模)ため見送り。**既存8カテゴリ(`EVENT_CATEGORIES`)を固定のまま**進める
3. 色そのものは、既存の `clay`(期限・要対応)/`honey`(調整中)と同じ oklch の明度・彩度(L≈70〜72% / C≈0.12〜0.13)を保ちつつ色相のみ変えて8色作成。ただし clay(H≈33°)・honey(H≈82°)の色相帯は、同じカード上にステータスバッジと並んで出るため意味の衝突を避けて外している。Artifact で実カード上にカテゴリ色+ステータス色を同居させて確認済み(https://claude.ai/code/artifact/978137e4-46ce-41d6-9c6b-3758bd2176d9 )、ユーザー承認済み

## トークン

`tailwind.config.ts` に `category` グループを追加、`design/tokens.css` に同値をミラーする(既存ルール通り両方同時更新)。値は承認済みの oklch 案を sRGB hex に変換したもの(枠内は色相の主観的な呼び名、実装上の意味は持たない)。

| カテゴリ(`EVENT_CATEGORIES`) | ラベル | hex | 由来 |
|---|---|---|---|
| `boardgame` | ボードゲーム | `#39bda0` | oklch(72% 0.12 175) |
| `snowboard` | スノボ | `#15bac6` | oklch(72% 0.12 203) |
| `travel` | 旅行 | `#44b2e2` | oklch(72% 0.12 231) |
| `movie_stage` | 映画・舞台 | `#76a5ef` | oklch(72% 0.12 259) |
| `nazotoki` | 謎解き | `#a098ec` | oklch(72% 0.12 287) |
| `live` | ライブ | `#c18dd8` | oklch(72% 0.12 315) |
| `drinking` | 飲み会 | `#d57cb4` | oklch(70% 0.13 343) |
| `other` | その他 | 新規トークンなし。既存の `subtle`(`#948a7d`)を流用 | — |

`design/rules.md` の「パステル差し色は装飾専用」の記述に、カテゴリ色8色の追加を明記する(手順の一部として更新する)。

## コンポーネント設計

既存の `Badge` / `BadgeTone`(`components/ui/server.tsx`)には手を入れない。理由: `BadgeTone` はステータス(調整中/期限/確定など)の意味を持つ既存の5トーンで、カテゴリは別軸の情報だから、同じ enum に混ぜると意味が読み取りにくくなる。

- 新規: `lib/domain/event/category-color.ts` — `EVENT_CATEGORIES` の各値を色クラスにマップする純粋関数(`categoryAccentClass(category): { bar: string; badgeBg: string; badgeText: string; dot: string }` のような形。既存の `lib/shared/constants.ts` の `categoryLabels` と対にして参照する
- 一覧カードの左帯(5px)は `border-l-4 border-l-[<hex>]` のTailwindユーティリティを `categoryAccentClass` から返す形で実装する(インラインスタイルは使わない。既存コードベースに前例が無く、Tailwindクラスの一貫性が崩れるため)。Tailwindの動的クラス名生成はビルド時にパージされるため、8色ぶんの完全なクラス名リテラルを `category-color.ts` 内のオブジェクトに書き切る(テンプレートリテラルで組み立てない)
- バッジは既存 `Badge` と見た目を揃える(`rounded-full`, `px-3 py-1`, `text-caption`, ドット付き)が、色は `categoryAccentClass` から取る専用マークアップにする(`Badge` コンポーネント自体は再利用しない — tone が合わないため)

## 適用範囲

`app/events/page.tsx` のイベント一覧カードのみ。各カードに:

- 左端5pxの色帯(カテゴリ色)
- カテゴリ名のドット付きバッジ(カード上部、既存の中止/完了などのステータス表示と並べる)

下書きカード(`visibleDraft` セクション)・絞り込みチップ・イベント詳細ヘッダー・カレンダー・つながり等は**今回のスコープ外**。

## テスト

`category-color.ts` の単体テスト(`tests/domain/category-color.test.ts`)で、8カテゴリすべてが期待するクラス文字列を返すことを確認する。jsdom は computed style を見られないため、クラス名の存在確認に留める(プロジェクト既存の作法)。一覧カードのレンダリングテストで、カテゴリごとに正しいバッジラベル・色クラスが出ることを確認する。
