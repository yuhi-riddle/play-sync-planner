# Phase 3-B Settlement Operations Design

## Goal

清算機能を「作れる」状態から「間違えても直せる」状態にする。立替支払いと参加者間の清算支払いを分け、一部清算を扱えるようにする。

## Terms

- `expenses`: 店、チケットサイト、代表者購入などに対する立替支払い。
- `settlements`: 相殺後に発生した、参加者間の請求。
- `settlement_payments`: `settlements` に対して実際に返した支払い。分割払い、一部清算、確認待ちをここで扱う。

## Scope

- 支払い前の立替支払いを編集できる
- 支払い前の立替支払いを削除できる
- 立替支払いを編集・削除したら清算結果を再計算する
- 清算支払いを一部金額で記録できる
- 清算ごとに支払い済み金額、残額、状態を表示する
- 清算支払いの受け取り確認を記録できる
- 支払い履歴と清算支払い履歴を画面上で分けて見せる

## Out Of Scope

- 外部決済API連携
- 支払い証拠画像アップロード
- 清算支払いが始まった後の立替支払い再計算
- 複数の古い清算結果にまたがる自動再割当

## Safety

`settlement_payments` が1件でもある場合、立替支払いの追加・編集・削除はブロックする。既に参加者間でお金が動いたあとに請求額を変えると、どの支払いが何に対応するか崩れるため。

## UI

清算画面では、次の3つを分ける。

- 立替支払いを追加
- 清算結果と清算支払い
- 立替支払い履歴

清算結果には、請求額、支払い済み額、残額、状態を表示する。残額がある場合だけ、一部支払いを記録できる。
