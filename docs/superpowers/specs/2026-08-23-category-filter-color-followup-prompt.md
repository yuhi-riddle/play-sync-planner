# 次回セッション用プロンプト: イベント一覧のカテゴリ絞り込みに色を出す

以下をそのまま次回セッションの最初のメッセージとして貼る。

---

play-sync-plannerで、イベント一覧(`/events`)のカテゴリ絞り込みにカテゴリの差し色を出したい。superpowers:brainstormingから始めて。

## 背景

イベントカテゴリの差し色機能(`lib/domain/event/category-color.ts`、8色)は既に一覧カードと詳細ページの見出しアイコンバッジに実装済み(`docs/superpowers/specs/2026-08-22-category-accent-expansion-design.md`参照)。残っているのは「絞り込みUIに色を出す」部分で、これが2026-08-22のセッションで詰まった。

## 詰まった経緯(重要、繰り返さないこと)

1. 最初、既存の`components/event/event-category-filter.tsx`(チップUI、mobileはselect/desktopはチップ)にドットを追加する計画を立てて実装した
2. **実装後の目視確認で、このコンポーネントがどのページからもimportされていない孤立コードだと判明**。`/events`の実際のカテゴリ絞り込みは`components/event/event-list-controls.tsx`内の、`<details>`で畳んだネイティブ`<select name="category">`(表示順・表示件数と同じフォーム内)。ブレインストーミング段階で「呼び出し元が実在するか」を確認していなかったのが原因
3. Task5(ドット追加)はrevertし(コミット`ce1341c`、ブランチ`feat/category-accent-expansion`)、Aの実現方法は別セッションで再検討することにした
4. 再検討で2案出したが、どちらもユーザーに「しっくり来ない」と却下された:
   - **案1: チップ行を状態チップの下に新設**。EventCategoryFilterを実際に配線し直す形。デメリット: 高さが+約40px増える。かつ2026-08-03に「カテゴリ・表示順・表示件数は畳んでおく」という明記された設計判断(375pxでセレクト4つ縦積み=629pxがファーストビューを潰した事故の反省)があり、これを部分的に覆すことになる
   - **案2: チップを使わず、畳んだ「条件を変える」の要約テキスト(`detailSummary`)にカテゴリ色を乗せるだけ**。高さ増分ゼロ。デメリット: 選ぶ操作は今のままselectのまま(タップで選ぶ体験は手に入らない)。かつ今回作ったEventCategoryFilterのチップ+ドットの実装を使わない
   - ユーザーの反応: 「どちらもしっくり来ない、他の形がありそう」

## 踏まえるべき制約(裏取り済みの事実)

- `components/event/event-list-controls.tsx`が実際に`/events`で使われているフィルタUI。カテゴリ・表示順・表示件数は`<details>`で畳んだ1つの`<form action="/events" method="get">`にまとまっている(1つの「表示する」ボタンで一括送信)
- 状態(進行中/下書き/完了/中止)だけは常時表示のチップ(`<nav aria-label="状態で絞り込む">`、横スクロール)。これは2026-08-03の設計判断で「実際に押されるのはほぼ状態だけ」という理由で特別扱いされている
- ネイティブ`<select>`の`<option>`には色を乗せられない(ブラウザ実装依存で信頼できない)。これは何度も出てきた制約で、覆らない
- `components/event/event-category-filter.tsx`(チップ+ドット実装、mobileはselect/desktopはチップ、Task5でドット追加→revert済み)は孤立コード。使うなら実際に配線し直す必要がある。かつ`eventFilterHref()`はカテゴリ以外のクエリパラメータ(検索語・状態・表示順・ページ番号)を全部捨てるURL構築関数なので、本物のフィルタとして繋ぐなら`buildEventListHref(query, page)`ベースに書き換えが要る
- カテゴリの色トークンは`categoryAccent(category).dot`(`bg-category-*`のTailwindクラス)。新規トークンは追加しない方針
- 375px幅での余白の使い方に、このプロジェクトは強いこだわりがある(`event-list-controls.tsx`内のコメントを読むこと)

## ブレストで検討すべき方向性(まだ検討していない案)

上の2案以外の「別の形」を探す。例えば(検証済みではない、たたき台):
- カテゴリだけ状態チップと**同じ横スクロール帯に混在**させる(別の段を作らない)
- 「条件を変える」を開いたときの**ネイティブselectをカスタムのカラー付きリストボックスに置き換える**(閉じてるときは高さゼロ、開いたときだけコストを払う)
- 状態チップの各チップ内に、現在のカテゴリ絞り込みを示す小さな色ドットを**間借りさせる**(新しいUI要素を増やさない)
- そもそも「絞り込み」ではなく「一覧カード側の色(実装済み)で十分」と割り切り、フィルタUI自体には手を入れない
- ユーザー自身に「他の形」のイメージがあるか、最初に聞く
