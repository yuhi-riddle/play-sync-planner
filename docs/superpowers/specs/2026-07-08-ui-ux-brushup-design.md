# Madoi UI/UX ブラッシュアップ設計

日付: 2026-07-08
ステータス: 承認済み

## 目的

リリース前に主要導線の見た目・文言・導線・スマホ幅を磨き、「本番で安心して使える」品質にする。
docs/current-status.md の「できれば確認する」4項目(画面文言と導線 / スマホ幅の入力しやすさ / 通知文面 / 清算ページの導線)に対応する。

## スコープ

### 対象画面(主要導線 13画面)

| 導線 | 画面 |
|---|---|
| 入口 | /login |
| ホーム | / (月カレンダー、選択日アジェンダ、対応事項) |
| イベント | /events (一覧+絞り込み)、/events/new、/events/[eventId] |
| 予定作成 | /events/[eventId]/plans/new (plan-form 4ステップ) |
| 回答 | /s/[token]/answer、/s/[token]/answer/complete |
| 確定 | /plans/[planId]、/plans/[planId]/confirm |
| 清算 | /plans/[planId]/settlement (主催者)、/s/[token]/settlement (公開) |
| 通知 | /notifications |
| 設定 | /settings |

### やること

- 見た目の磨き込み: AIっぽい定型スタイルの解消、状態(hover/focus/empty/error/loading)の欠落補完
- 文言の見直し: 画面文言・通知文面・エラーメッセージの分かりやすさ
- 導線の改善: ユーザーが迷う流れは変更してよい(承認済み)。必要なら小さな新規画面・追加機能も可
- スマホ幅(375px目安)での入力しやすさ・崩れの修正
- 既存デザイントーン(cream/moss/ink の和風パレット)は維持したまま磨く

### やらないこと

- デザインの全面刷新(トーンごと変えるのは別タスク)
- 後続Phase候補(LINE/Discord連携、決済API、PWA通知など)
- 目的に直結しない DB スキーマ変更(導線改善に必要な軽微な変更は相談のうえ可)

## 進め方(3フェーズ)

### フェーズ1: コード診断

frontend-design-fix-sync スキルの観点で対象コンポーネントを診断する。

- 観点: AIっぽさ、状態の欠落、文言、導線の迷い、スマホ幅
- 成果物: 重要度つきの問題リスト
- **修正前にリストをユーザーに見せて合意する**(勝手に大改造しない)

### フェーズ2: 修正

- 合意した問題だけ直す
- 導線変更・画面追加を伴うものは、ビジュアルコンパニオンでモックを見せて選んでもらう
- 各修正のまとまりごとに `npm.cmd test` を回し、壊れたらその場で直す

### フェーズ3: 実機確認

1. dev server を起動し、ユーザーに一度 Google ログインしてもらう
2. visual-qa でデスクトップ+スマホ幅のスクリーンショットを撮る
3. コード診断で拾えなかった視覚問題を修正する
4. accessibility スキルでキーボード操作・ARIA をチェックする
5. `npm.cmd test` + `npm.cmd run build` を通してコミットする

## エラーハンドリング

- テストが壊れたら systematic-debugging の手順で根本原因から直す
- 判断が分かれる視覚案(色・レイアウト)はビジュアルコンパニオンで比較提示する

## テスト方針

- 既存の vitest スイート(200件)を常にグリーンに保つ
- 導線変更した画面は対応するコンポーネントテストも更新する
- 新規画面を作る場合は既存テストのパターン(testing-library)に合わせてテストを追加する

## 完了条件

- 主要導線 13画面の診断・修正・実機確認が済んでいる
- `npm.cmd test` と `npm.cmd run build` が通る
- 変更がコミットされている
