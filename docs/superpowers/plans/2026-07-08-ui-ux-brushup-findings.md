# UI/UX 診断結果

Madoi の主要導線を、グループ A〜F と共通(CM)に分けてコード診断した結果です。
観点は「AIっぽさ / 状態の欠落 / 文言 / 導線 / スマホ幅(375px)」の5つ。清算(E)は「支払う側・受け取る側が迷わないか」、通知(F)は「文面が分かりやすいか」を重点に見ています。
重要度は 高=直さないと迷う・困る / 中=直すと明確に良くなる / 低=好みの範囲、の3段階です。

全体所感: 和風パレット・自作ロゴ・祝日配色など独自性は十分で、「無個性なAIっぽさ」はほぼありません。問題は主に「用語のばらつき」「送信できない理由が出ない」「清算画面の情報過多」に集中しています。

---

## 高(直さないとユーザーが迷う・困る)

- [ ] G-CM-1: (全体の導線) 同じ対象の呼び名がバラバラ。ホームの導線は「イベント一覧 / イベント作成」(`app/page.tsx` の `homeActions`)なのに、遷移先は「予定一覧 / 予定作成」(`app/events/page.tsx`)、新規作成は「予定を作る」(`app/events/new/page.tsx`)、編集は「イベント編集」(`app/events/[eventId]/edit/page.tsx`)と混在。さらに plan は「日程調整」「調整カレンダー」「調整」と揺れています。押した言葉と着地ページの見出しが食い違い、正しい場所に来たか不安になる。→ 用語を1組に統一する。推奨は「イベント=予定の箱」「日程調整=候補集め」の2語に固定し、`app/page.tsx` / `app/events/page.tsx` / `app/events/new/page.tsx` / `app/events/[eventId]/edit/page.tsx` の見出し・ボタン・説明文を合わせる。まず全画面で「イベント」か「予定」かどちらか片方に寄せるだけでも効果大。

- [ ] G-D-1: (日程回答 `components/answer-form.tsx`) 全候補に回答するまで「回答する」ボタンが `disabled` のまま。なぜ押せないかの説明が近くに無く、「回答済み X/Y」カウンター(上部)と離れているため、回答者が固まる。公開回答は初見ユーザーが多く、ここで詰まると致命的。→ 送信ボタンの直前に未回答時のヘルプを出す。例:未回答が残るとき `残り{n}件の候補に回答すると送信できます。` を `aria-live="polite"` で表示。あわせて未回答の候補カード枠を強調(border-clay など)して場所を示す。

- [ ] G-E-1: (公開清算 `components/public-settlement-summary.tsx` / `app/s/[token]/settlement/page.tsx`) 「支払い先」に全員ぶんの `fromName → toName` が並ぶだけで、リンクを開いた本人がどれを払えばいいのかの案内が無い。本人を特定する情報も無いため、支払う側が自分の行を探せず迷う。→ 見出し下に案内文を追加。例:`自分の名前が「支払う人」になっている行から支払ってください。` さらに `fromName`(支払う人)を太字・色付きにして視線を誘導する。個人を絞り込む機能追加はDBに影響しないが、まずは文言と強調だけで解消できる。

## 中(直すと明確に良くなる)

- [ ] G-E-2: (清算 `app/plans/[planId]/settlement/page.tsx`) 立替が0件でも「清算の進捗」「次にやること」「受け取り確認待ち」など空のカードが最初から全部並ぶ。何もしていないのに「支払い待ち0件」等が続き、最初に何をすればいいかが埋もれる。→ `expenses.length === 0` のときは進捗・次アクション系カードを隠し、「まず支払いを追加しましょう」という単一の導入カード+`ExpenseForm` だけを見せる。データが入ってから進捗カードを出す。

- [ ] G-E-3: (清算 全体の情報設計 `app/plans/[planId]/settlement/page.tsx`) 主催者画面が縦に約10枚のカードが並ぶ長大な1カラムで、支払い依頼・確認依頼・送信記録・清算結果・支払い履歴が同列。目的の操作にたどり着くまでスクロールが長い。→ 主催者向けツール(依頼文面・送信記録)を「参加者に依頼する」など折りたたみ or セクション見出しでグルーピングし、上部は「進捗」「次にやること」「清算結果」に絞る。DB変更不要のレイアウト調整。

- [ ] G-E-4: (PayPay `components/paypay-action-panel.tsx`) 「PayPayを開く」は `window.location.href = "paypay://"`。PCや未インストール端末では何も起きず、押しても無反応で戸惑う。→ ボタン下に `スマホのPayPayアプリがある場合に開きます。` の補足を添える。あるいはクリック後一定時間で遷移しなければ「アプリが見つかりませんでした」を出す。最低限は補足文の追加。

- [ ] G-C-1: (日程調整作成 `components/plan-form.tsx` L661) ステップ表示が4項目なのに `sm:grid-cols-3`。タブレット〜PC幅で「3+1」の不揃いな2段になる。→ `sm:grid-cols-2 lg:grid-cols-4`(または `grid-cols-4`)にして、4ステップが1段またはきれいな2×2で並ぶようにする。見た目だけの変更でテスト不要。

- [ ] G-CM-2: (共通のタップ領域) 制約は最小44px(min-h-11)だが、実際は多くの操作要素が40px(`min-h-10` / `h-10 w-10`)。例:ヘッダーの通知・設定・ログアウト(`components/auth-nav.tsx`)、月送り矢印(`components/home-month-calendar.tsx` / `adjustment-calendar-view.tsx`)、`ButtonLink`/`SecondaryLink`(`components/ui.tsx`)、各フィルタチップ。375px でのタップミスにつながる。→ 主要な操作要素を `min-h-11` / `h-11 w-11` に引き上げる。特にヘッダーのアイコンボタンと月送り矢印を優先。

- [ ] G-E-5: (清算 `app/plans/[planId]/settlement/page.tsx`) ログイン済みの「支払う参加者」がこの画面を開いても、支払い記録の操作は `canManage`(主催者のみ)で隠れており、受け取り側でない限り何もできない。公開リンクへ誘導する導線も無く、自分の操作が見つからない。→ 非主催者かつ未払いがある場合に「支払いは参加者向け清算リンクから行えます」の案内、または公開清算ページへのリンクを出す。

- [ ] G-B-1: (イベント詳細 `app/events/[eventId]/page.tsx` L57) 日程調整カードのリンクが Next の `Link` でなく生の `<a>` で、毎回フルリロード。また一覧へ戻る導線が無く、共通の「ホームへ」だけでイベント一覧に戻れない。→ `<a>` を `next/link` の `Link` に置き換え。ページ下部か見出しに「予定一覧へ」`SecondaryLink href="/events"` を追加する。

- [ ] G-F-1: (通知/ホーム 文言のずれ) ホームの絞り込みは「確認待ち」(`app/page.tsx` の `actionFilterOptions`)だが、通知一覧の種別ラベルは「受け取り確認」(`app/notifications/page.tsx` の `kindLabels`)。同じ対象を別語で呼んでいて、絞り込みと通知本文が対応して見えない。→ どちらかに統一(「受け取り確認」推奨)。両ファイルのラベルを合わせる。

## 低(好みの範囲・余裕があれば)

- [ ] G-A-1: (ホーム `components/home-month-calendar.tsx`) このコンポーネントはテスト以外から参照されておらず、実際のホーム(`app/page.tsx`)は `HomeSelectedDateAgenda` のみ描画。月カレンダーは未使用の状態。→ 月表示をホームに出す方針なら配置する。出さないなら混乱・保守コスト回避のため削除を検討(要方針確認)。

- [ ] G-CM-3: (共通 空状態のばらつき) 空状態が、共通 `EmptyState`(`components/ui.tsx`)と、その場書きの破線 div(`home-month-calendar.tsx` L308、`plan-form.tsx` の `SelectedCandidates` など)で混在。見た目が微妙に違う。→ できる範囲で `EmptyState` に寄せて統一する。見た目だけの変更。

- [ ] G-C-2: (日程調整作成 `components/plan-form.tsx` L636) 回答期限が候補日時より後のとき「次へ」を押すと `moveToStep` が黙って return し、メッセージも消える。ステップ1に出ている赤枠の注意書きが唯一の手がかり。→ 「次へ」時に `message` を消さず、期限を直す旨を明示する(赤枠は残っているので優先度低)。

- [ ] G-D-2: (回答完了 `app/s/[token]/answer/complete/page.tsx`) 「支払い・清算を見る」が常時表示で、清算未登録だと遷移先で「まだ清算内容は登録されていません。」に着地し軽い行き止まり。→ 清算が存在するときだけリンクを出す(要データ取得)か、リンク文言を「予定が確定したら清算もここから見られます」に和らげる。

- [ ] G-E-6: (清算 `components/settlement-progress-steps.tsx`) 「完了」ステップの件数ラベルが未完了時「未完了」/完了時「3/3」と表記の種類が変わり、他ステップの「N件」と粒度が揃わない。→ 表記を「◯/◯」か「N件」系に統一して一貫させる。見た目だけ。

- [ ] G-F-2: (設定 `app/settings/page.tsx` / `components/account-email-card.tsx`) 設定はアカウントとGoogle連携の2枚のみで、通知やリマインドの設定入口が無い。ユーザーが「通知を止めたい」等でここを探すと空振りする可能性。→ 現状維持でよいが、将来的に通知設定を置くなら設定ページに集約する(要方針・スキーマ確認)。
