# Madoi 要件定義書 v1.7

最終更新: 2026-07-06

## 1. 概要

Madoi は、友人同士の遊び、謎解き公演、ライブ、飲み会などの日程を合わせるための Web アプリです。

開発プロジェクト名とリポジトリ名は `play-sync-planner` のままですが、画面上のサービス名は `Madoi` とします。

## 2. 目的

まずは「予定を合わせて、確定した予定をスケジュールに入れる」ことに集中します。

イベント作成時に細かい費用や清算情報まで求めすぎると入力が重くなるため、日程調整を優先します。清算や支払い履歴は、日程調整後に扱う機能として分けます。

## 3. 対象ユーザー

- 友人と複数人で予定を立てる人
- 謎解き公演、ライブ、展示、飲み会などの候補日時をまとめたい人
- 複数の調整中予定をカレンダーで見比べたい人
- Google Calendar の予定を見ながら候補日時を決めたい人

## 4. 基本方針

- 日程調整に必要な入力を優先する
- イベント作成時に不要な詳細情報は必須にしない
- 候補日時と回答期限はステップ分割して入力しやすくする
- 候補日時はカレンダー UI で選べるようにする
- 過去日時は候補に追加できない
- 回答期限は最初の候補日時より前にする
- 謎解きカテゴリでは `10:00 / 13:00 / 16:00 / 19:00` の時間テンプレートを使えるようにする
- 共有リンクを踏んだ人は、回答時に名前を入力して参加者になる

## 6. Phase 2 実装済み範囲

Google Calendar 連携により、候補日時作成・編集画面と回答画面で自分の予定を確認できます。Google Calendar 連携は任意です。日程確定後、主催者が「Calendarに作成して招待」を押すと、主催者の Google Calendar に予定を作成し、Google Calendar 連携済みの参加者へ招待を送ります。連携していない人向けには、手動でGoogle Calendarに追加できる導線も残します。

取得する Google Calendar 情報:

- 予定の開始時刻
- 予定の終了時刻
- 予定名
- 場所

Google Calendar 作成・追加で扱う情報:

- 確定した予定名
- 確定した開始時刻
- 確定した終了時刻
- 場所

取得しない情報:

- 予定の説明
- 参加者
- Meet URL
- 添付ファイル
- その他の予定詳細

保存方針:

- Google Calendar の予定詳細はデータベースに保存しない
- 連携用トークンのみ暗号化して保存する
- 予定名と場所は、ログイン中の本人の画面表示にだけ使う
- 共有リンク回答者や他の参加者には表示しない
- 確定した瞬間には自動登録せず、主催者のボタン操作でGoogle Calendar作成と招待を行う

OAuth スコープ:

```text
https://www.googleapis.com/auth/calendar.events
```

## 7. Phase 2 でまだ実装しないもの

- LINE、メール、Discordなどへの自動リマインド送信
- 自動候補日時提案
- 参加者全員のカレンダーを集めた自動調整
- Google Calendar 予定詳細のDB保存

## 8. Phase 3-A 実装済み範囲

清算は、Walicaそのものを再現するのではなく、複数人の予定調整に必要な部分だけを先に実装します。

- 参加予定ごとの支払い履歴追加
- 支払った人の選択
- 負担者の選択
- 均等割り
- 個別金額
- 清算結果の自動計算
- 誰が誰にいくら払うかの表示
- 支払い済み登録
- 受け取り確認
- 支払い方法メモ
- 支払い用URL
- 清算リマインド文面コピー
- 清算リマインド送信済み記録

制約:

- 支払い済みまたは受け取り確認済みの清算がある場合、費用追加はブロックする
- 外部決済APIとの直接連携はまだ実装しない
- LINE、Discord、メールなどへの自動送信はまだ実装しない

## 9. Phase 3-B 実装済み範囲

清算支払いは、立替支払いとは別の履歴として扱います。これにより、清算の一部支払いと受け取り確認を扱えるようにします。

- 立替支払いの編集
- 立替支払いの削除
- 清算支払いが始まった後の立替支払い変更ロック
- 清算支払いの一部金額登録
- 清算支払いごとの支払い方法メモ
- 清算支払いごとの支払い用URL
- 清算支払いごとの受け取り確認
- 残額ベースの清算リマインド文面
- 支払い履歴の重要メモ表示
- 清算状況サマリー
- 支払いURLを開く導線
- 支払い依頼文面コピー
- 支払い先メモ保存

方針:

- `expenses` は、チケット代や立替など、誰かが先に払った支払い履歴として扱う
- `settlements` は、支払い履歴から計算した「誰が誰にいくら払うか」として扱う
- `settlement_payments` は、清算結果に対して実際に払った履歴として扱う
- 一部清算があるため、清算支払いは `settlements` に直接上書きしない
- 予約番号や当日必要な情報は、支払い履歴のメモを重要表示することで扱う
- 画像アップロードだけの証跡管理はしない。やるならOCRやメール解析まで含めた後続機能として別途検討する

制約:

- 清算支払いが1件でも記録された後は、立替支払いの追加・編集・削除をブロックする
- 清算支払いの合計が請求額を超える場合は保存しない
- 外部決済APIとの直接連携はまだ実装しない
- 支払いURLや購入ページURLを開く導線は表示する
- 支払い依頼文面はコピーできるが、自動送信はまだ実装しない

## 10. Phase 3-C 実装済み範囲

外部決済API連携の前段として、支払い依頼を手動で送りやすくします。

- 清算ごとに支払い方法、支払い先URL、メモを保存する
- 未払いの清算だけを対象に支払い依頼文面を生成する
- 支払い依頼文面に残額、支払い先URL、メモを含める
- 文面コピーと送信済み記録を使える

制約:

- PayPayなどの外部決済API連携はまだ実装しない
- LINE、Discord、メールなどへの自動送信はまだ実装しない
- 入金確認の自動化はまだ実装しない

## 11. サイト内通知 実装済み範囲

Madoi内で、対応が必要なものを通知として確認できます。

- ヘッダーに未読通知件数を表示する
- ホームに対応が必要な通知を表示する
- `/notifications` で通知一覧を表示する
- 未読通知だけを初期表示する
- 既読フィルターで既読済み通知を確認できる
- 通知を1件ずつ既読にできる
- 未読通知をまとめて既読にできる
- 日程回答が送信されたら、主催者へ即時に通知する
- 通知生成APIをVercel Cronから実行できる
- 回答期限前のサイト内通知は、参加予定ごとの複数リマインド設定に沿って生成する
- 同じ内容の通知を重複作成しない

通知対象:

- 回答期限が近い日程調整
- 未回答者がいる日程調整
- 日程回答が届いた日程調整
- 清算が必要な予定
- 支払い待ち
- 受け取り確認待ち

制約:

- 現時点では、メール、LINE、Discord、Xなどへの自動送信はしない
- 通知はMadoi内で表示する
- 通知の手動確認を前提にする

## 14. 注意事項

- Google Calendar 連携を追加・変更した場合は、取得するスコープと利用目的をプライバシーポリシーへ明記する
- 予定名や場所を扱う場合でも、本人の画面表示に限定し、他者へ共有しない
- OAuth スコープ変更後は、既存ユーザーに再連携が必要になる
- 正式公開前に、利用規約・プライバシーポリシー・問い合わせ先を見直す

## 15. 利用開始時の同意と下書き

- Google ログインを始める前に、利用規約とプライバシーポリシーへの同意を必須にする
- 同意した日時と規約の版数をユーザーごとに保存する
- 同意記録がないログイン済みユーザーは、通常画面ではなく同意画面へ案内する
- イベント作成途中の内容は下書きとして保存できる
- 下書きは進行中のイベント一覧には出さず、「下書き」に絞り込んだ場合だけ表示する
- 通常のイベント作成は空のフォームを開き、保存済み下書きは「続きから入力」からだけ再開する
- 初回ログイン後にニックネームを確認し、任意でプロフィール画像を設定できる

## 16. 参加者権限とCalendar空き状況

- イベント情報、参加者募集、日程調整の開始、中止は主催者だけが変更できる
- 参加者はイベント情報を閲覧し、日程回答と自身に必要な操作だけを行う
- 参加者数はRLSの見え方に左右されず、イベント詳細で正確な参加済み人数を表示する
- Google Calendarの空き状況集計では、予定のタイトル・場所・説明を参加者間で共有しない
- 空き状況取得に必要なGoogle権限が不足している場合は、再連携を促す

## 17. つながり、招待、共同調整

- 同じイベントに参加済みのユーザーだけを、片方向でフォローできる
- フォロー済みの相手だけをお気に入りに登録できる
- ブロックすると、双方のフォローとお気に入りを解除し、以後のフォローとアプリ内招待を禁止する
- イベント主催者は、過去に共通イベントへ参加したユーザー、フォロー中またはお気に入りのユーザーをアプリ内で招待できる
- 招待されたユーザーは通知一覧またはつながり画面から承諾・辞退でき、承諾した場合だけ参加者になる
- イベント内チャットは参加済みメンバーだけが閲覧・投稿できる。リアルタイム配信、添付、編集、削除は現時点では扱わない
- 参加者のGoogle Calendar予定は、主催者が日程調整中に集計結果としてだけ確認できる。予定名、場所、説明、個人別の予定は表示・保存しない
- 日程を再調整すると、確定日時と日程回答を取り消し、参加者の回答待ち状態へ戻す。空き状況は保存せず、主催者が必要なタイミングで再取得する
## 18. 持ち物・役割の分担

- イベント単位で、当日までに用意するものと担当を書き出せる
- 担当者は、そのイベントに参加済みのメンバーから選ぶ。担当なしのままでもよい
- 参加済みのメンバーなら誰でも、追加・担当の変更・完了の切り替え・削除ができる
- 中止したイベントでは編集できない
- 日程調整や清算とは連動させない。準備は日程が決まる前から始まるため、イベントに紐づける

## 追加メモ: Phase 2 ホーム日付表示とカレンダー

ホーム画面では、選択した1日の予定と対応が必要な通知に絞って表示します。自分が参加している複数の調整を月単位で見比べる画面は、カレンダーに分けます。

- ホームでは今日、明日、週末、任意の日付で表示日を切り替えられる
- ホームでは選択日の予定だけをタイムラインで表示する
- ホームでは対応が必要な通知を、期限、未回答、清算、支払い、確認待ちで絞り込める
- カレンダーではMadoiの調整中候補を黄色で表示する
- カレンダーではMadoiの確定済み予定を緑で表示する
- カレンダーではGoogle Calendarの予定を青で表示する
- カレンダーでは、候補ごとの回答数とGoogle Calendar予定を同じタイムラインで確認できる
- Google Calendarの予定はDBに保存せず、画面表示時に取得する
- 日付選択や月移動では、不要にページ上部へ戻らないようにする
## 追加メモ: Phase 2 回答画面のGoogle Calendar確認

共有リンクの日程回答画面では、ログイン済みかつGoogle Calendar連携済みの場合、自分のGoogle Calendar予定と候補日時の重なりを見ながら回答できるようにします。

- 候補日時とGoogle Calendar予定が重なる場合は注意表示する
- 注意表示には予定名、場所、時間を表示する
- 未ログイン、未連携、取得失敗の場合でも回答自体は止めない
- Google Calendarの予定詳細はDBに保存しない
## 追加メモ: Phase 2 日程確定の判断画面

作成者が日程を確定しやすいように、予定詳細と日程確定画面では候補日時をランキング表示します。

- ○が多い候補を優先する
- 同数なら△が多い候補を優先する
- ×が少ない候補を優先する
- 未回答が少ない候補を優先する
- おすすめ、未回答あり、スコア、回答率を表示する
- 確定前に確認ダイアログを出す

## 追加メモ: Phase 2 未回答者とリマインド文面

予定詳細画面では、参加者のうち未回答の人を一覧で確認できるようにします。

- 未回答者は `participants.status = invited` の参加者として扱う
- 未回答者がいる場合、回答期限と共有リンクを含むリマインド文面を生成する
- 回答期限の何分前・何時間前・何日前に声をかけるかを参加予定ごとに保存する
- 保存した複数のリマインダー設定は予定詳細とリマインド文面に反映する
- 手動で連絡したあと、送信済みとして記録できるようにする
- 送信済み記録では前回送信時刻と記録回数を表示する
- 文面はコピーできるようにし、送信はユーザーが普段使う連絡手段で手動で行う
- LINE、メール、Discordなどへの自動送信はまだ実装しない

## 追加メモ: Phase 2 終日候補

候補日時作成画面では、候補を終日として追加できます。

- 終日候補は `candidate_dates.is_all_day` に保存する
- 終日の開始は選択日の `00:00`、終了は翌日の `00:00` として扱う
- 表示上は時刻ではなく「終日」と表示する
- 日程確定時は `plans.is_all_day` にも反映する
- Google Calendar に追加ボタンでは、終日予定として扱えるようにする
