# Madoi 要件定義書 v1.2

最終更新: 2026-06-28

## 1. アプリ概要

Madoi は、友人同士の遊び予定について、候補日時を出し、参加者に回答してもらい、日程を確定するためのWebアプリです。

プロジェクト名とリポジトリ名は `play-sync-planner` のままですが、画面上のサービス名は **Madoi** とします。

最初のPhase 1では、清算や外部連携よりも「予定を合わせる」体験を優先します。謎解き公演での利用を強く意識しつつ、ライブ、旅行、飲み会、スノボ、ボードゲーム会などにも広げられる構造にします。

## 2. 現在の中心価値

Phase 1で一番大事にする価値は、次の3つです。

- 複数の予定調整が同時に走っていても、何をいつ調整しているか分かる
- 候補日時に対して、参加者がすぐ回答できる
- 主催者が回答状況を見て、日程を確定できる

Google Calendar連携、自動空き時間提案、リマインド、清算は重要ですが、Phase 1では実装しません。後続Phaseで足しやすいように、DBと画面導線だけ拡張余地を残します。

## 3. 背景・課題

謎解きや友人との遊び予定では、以下のような困りごとが起きやすいです。

- 行きたい公演や遊び予定が複数あり、どれが調整中なのか分からなくなる
- 候補日を出したあと、誰が回答済みか追いにくい
- 別の予定調整と候補日時がぶつかっているか見えにくい
- 日程確定後、参加者に確定日時を共有し直すのが面倒
- 将来的には、チケット代や食事代の清算も同じ予定に紐づけて管理したい

## 4. 対象ユーザー

### Phase 1の対象ユーザー

- 友人と複数人で遊び予定を立てる人
- 謎解き公演、ライブ、飲み会などの候補日時をまとめたい人
- 共有リンクで、ログインしていない相手にも回答してもらいたい人
- 複数の予定調整をカレンダーで見比べたい人

### 将来的な対象ユーザー

- チケット代や旅行費などをあとで清算したい人
- Google Calendarの空き状況を見ながら候補日時を決めたい人
- 回答期限や開催前リマインドを自動で送りたい人

## 5. 基本方針

- Phase 1は日程調整に集中する
- 予定作成時に余計な詳細情報を求めすぎない
- まずカテゴリ、予定名、場所メモなどの基本情報だけ入力する
- 候補日時と回答期限は、予定作成後のステップで入力する
- 候補日時はカレンダーUIで選ぶ
- 日付選択時にページ先頭へ戻らないなど、細かい操作ストレスを減らす
- 謎解きカテゴリでは、10:00 / 13:00 / 16:00 / 19:00 の時間テンプレートを使える
- 終日候補はDBに拡張余地を残し、UIはGoogle Calendar連携と一緒にPhase 2で実装する
- 共有リンクを踏んだ人は、名前を入力して回答できる
- PCでも使えるが、スマホ利用を強く意識する

## 6. 主要概念

### 予定

遊び予定の元になる情報です。内部DBでは `events` として扱いますが、画面上はできるだけ「予定」と呼びます。

### 日程調整

予定に対して作る、候補日時と回答状況のまとまりです。内部DBでは `plans` として扱います。

### 候補日時

参加者へ提示する日時候補です。開始日時、終了日時、終日フラグを持ちます。

### 参加者

日程調整に参加する人です。共有リンクから回答した人も参加者として扱います。

### 日程回答

候補日時ごとの参加可否です。

- ○: 行ける
- △: 微妙
- ×: 行けない
- 未回答

### 調整カレンダー

複数の日程調整の候補日時を月表示で見比べる画面です。どの日に候補があり、どの時間帯が重なっているかを確認します。

## 8. 機能要件

### 認証

- Googleログインに対応する
- 予定作成、日程調整作成、日程確定にはログインが必要
- 共有リンクからの日程回答は未ログインでも使える

### 予定登録

入力項目:

- カテゴリ
- 予定名
- URL
- 場所メモ
- メモ

Phase 1では、開催日時、料金、定員などは必須にしません。必要になったら後で編集できる設計にします。

### 日程調整作成

入力項目:

- 候補日時
- 回答期限
- メモ

候補日時:

- カレンダーで日付を選ぶ
- 開始時間と終了時間を入力する
- 時刻は1分単位で入力できる
- 終日候補はPhase 2で対応する
- 連日候補に対応する
- 過去日は追加できない
- 回答期限が候補日時より後の場合はエラーにする

### 参加者管理

- 共有リンクから回答した人を参加者として登録する
- ゲスト参加者は回答時に名前を入力する
- 主催者は参加者一覧と回答状況を見られる

### 日程回答

- 共有リンクから候補日時へ回答できる
- 回答は ○ / △ / × から選ぶ
- 回答者は名前とコメントを入力できる
- 回答期限を過ぎた場合は回答できない

### 日程確定

- 主催者は候補日時の中から1つを確定できる
- 確定後、日程調整のステータスを `date_confirmed` にする
- 確定候補に ○ または △ と回答した参加者を参加予定として扱う
- × の参加者は不参加扱いにする

### 調整カレンダー

- 月表示で候補日時を確認できる
- 候補がある日は件数を表示する
- 同じ開始時刻の候補が複数ある日は重なりを表示する
- 確定済み候補がある日を区別する
- 日付を選ぶと、その日の候補をタイムラインで確認できる
- 日付選択や月移動でページ先頭へ戻らない
- 月またぎの日付を選ぶと、その日付の月へ移動する
- 表示中の年月を押して、見たい月へ直接移動できる
- 土曜・日曜は色で区別する
- タイムラインでは候補日時の開始〜終了を表示する

## 10. 後続Phase候補

### Phase 2候補

- 自分のGoogle Calendar予定を見ながら候補日時を決める
- 確定日時をGoogle Calendarへ登録する
- 終日候補の入力とGoogle Calendar登録

### Phase 3候補

- 支払い履歴

### Phase 4候補

- 外部共有の強化
- LINE / Discord / X 連携
- PWA通知

## 11. 現時点の注意点

- 規約とプライバシーポリシーはドラフトであり、正式公開前に運営者情報、問い合わせ先、実際に扱うGoogleデータを確定する
- Google Calendar連携を追加する場合は、取得するスコープと利用目的をプライバシーポリシーへ明記する
- 内部DB名は `events` / `plans` のままでもよいが、画面上はユーザーに分かりやすい「予定」「日程調整」を優先する
