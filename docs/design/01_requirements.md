# Madoi 要件定義書 v1.6

最終更新: 2026-07-01

## 1. 概要

Madoi は、友人同士の遊び、謎解き公演、ライブ、飲み会などの日程を合わせるための Web アプリです。

開発プロジェクト名とリポジトリ名は `play-sync-planner` のままですが、画面上のサービス名は `Madoi` とします。

## 2. 目的

まずは「予定を合わせて、確定した予定をスケジュールに入れる」ことに集中します。

イベント作成時に細かい費用や清算情報まで求めすぎると入力が重くなるため、日程調整を優先します。清算や支払い履歴は、日程調整後に扱う機能として分けます。

## 3. 対象ユーザー

- 友人と複数人で予定を立てる人
- 謎解き公演、ライブ、展示、飲み会などの候補日時をまとめたい人
- 複数の調整中予定をカレンダーで見比べたい人
- Google Calendar の予定を見ながら候補日時を決めたい人

## 4. 基本方針

- 日程調整に必要な入力を優先する
- イベント作成時に不要な詳細情報は必須にしない
- 候補日時と回答期限はステップ分割して入力しやすくする
- 候補日時はカレンダー UI で選べるようにする
- 過去日時は候補に追加できない
- 回答期限は最初の候補日時より前にする
- 謎解きカテゴリでは `10:00 / 13:00 / 16:00 / 19:00` の時間テンプレートを使えるようにする
- 共有リンクを踏んだ人は、回答時に名前を入力して参加者になる

## 5. Phase 1 実装済み範囲

- Googleログイン
- イベント登録
- イベント編集
- 参加予定作成
- 候補日時登録
- 回答期限登録
- 参加者管理
- 共有リンク生成
- 未ログイン回答
- 日程回答
- 日程確定
- 調整カレンダー
- 利用規約・プライバシーポリシーのドラフト表示

## 6. Phase 2 実装済み範囲

Google Calendar 連携により、候補日時作成・編集画面で自分の予定を確認できます。日程確定時には、確定した日程を連携中の Google Calendar へ予定として作成します。

取得する Google Calendar 情報:

- 予定の開始時刻
- 予定の終了時刻
- 予定名
- 場所

作成する Google Calendar 情報:

- 確定した予定名
- 確定した開始時刻
- 確定した終了時刻
- 場所

取得しない情報:

- 予定の説明
- 参加者
- Meet URL
- 添付ファイル
- その他の予定詳細

保存方針:

- Google Calendar の予定詳細はデータベースに保存しない
- 連携用トークンのみ暗号化して保存する
- 予定名と場所は、ログイン中の本人の画面表示と確定予定の作成にだけ使う
- 共有リンク回答者や他の参加者には表示しない

OAuth スコープ:

```text
https://www.googleapis.com/auth/calendar.events
```

## 7. Phase 2 でまだ実装しないもの

- LINE、メール、Discordなどへの自動リマインド送信
- 自動候補日時提案
- 参加者全員のカレンダーを集めた自動調整
- Google Calendar 予定詳細のDB保存

## 8. Phase 3-A 実装済み範囲

清算は、Walicaそのものを再現するのではなく、複数人の予定調整に必要な部分だけを先に実装します。

- 参加予定ごとの支払い履歴追加
- 支払った人の選択
- 負担者の選択
- 均等割り
- 個別金額
- 清算結果の自動計算
- 誰が誰にいくら払うかの表示
- 支払い済み登録
- 受け取り確認
- 支払い方法メモ
- 支払い用URL
- 清算リマインド文面コピー
- 清算リマインド送信済み記録

制約:

- 支払い済みまたは受け取り確認済みの清算がある場合、費用追加はブロックする
- 外部決済APIとの直接連携はまだ実装しない
- LINE、Discord、メールなどへの自動送信はまだ実装しない

## 9. Phase 3-B 実装済み範囲

清算支払いは、立替支払いとは別の履歴として扱います。これにより、清算の一部支払いと受け取り確認を扱えるようにします。

- 立替支払いの編集
- 立替支払いの削除
- 清算支払いが始まった後の立替支払い変更ロック
- 清算支払いの一部金額登録
- 清算支払いごとの支払い方法メモ
- 清算支払いごとの支払い用URL
- 清算支払いごとの受け取り確認
- 残額ベースの清算リマインド文面
- 支払い履歴の重要メモ表示

方針:

- `expenses` は、チケット代や立替など、誰かが先に払った支払い履歴として扱う
- `settlements` は、支払い履歴から計算した「誰が誰にいくら払うか」として扱う
- `settlement_payments` は、清算結果に対して実際に払った履歴として扱う
- 一部清算があるため、清算支払いは `settlements` に直接上書きしない
- 予約番号や当日必要な情報は、支払い履歴のメモを重要表示することで扱う
- 画像アップロードだけの証跡管理はしない。やるならOCRやメール解析まで含めた後続機能として別途検討する

制約:

- 清算支払いが1件でも記録された後は、立替支払いの追加・編集・削除をブロックする
- 清算支払いの合計が請求額を超える場合は保存しない
- 外部決済APIとの直接連携はまだ実装しない

## 11. 注意事項

- Google Calendar 連携を追加・変更した場合は、取得するスコープと利用目的をプライバシーポリシーへ明記する
- 予定名や場所を扱う場合でも、本人の画面表示に限定し、他者へ共有しない
- OAuth スコープ変更後は、既存ユーザーに再連携が必要になる
- 正式公開前に、利用規約・プライバシーポリシー・問い合わせ先を見直す
## 追加メモ: Phase 2 ホーム月カレンダー

ホーム画面では、複数の調整中イベントを横断して見られる月カレンダーを表示します。

- Madoiの調整中候補を黄色で表示する
- Madoiの確定済み予定を緑で表示する
- Google Calendarの予定を青で表示する
- 日付を選ぶと、その日の予定をタイムラインで表示する
- Google Calendarの予定はDBに保存せず、画面表示時に取得する
- 日付選択や月移動では、不要にページ上部へ戻らないようにする
## 追加メモ: Phase 2 回答画面のGoogle Calendar確認

共有リンクの日程回答画面では、ログイン済みかつGoogle Calendar連携済みの場合、自分のGoogle Calendar予定と候補日時の重なりを見ながら回答できるようにします。

- 候補日時とGoogle Calendar予定が重なる場合は注意表示する
- 注意表示には予定名、場所、時間を表示する
- 未ログイン、未連携、取得失敗の場合でも回答自体は止めない
- Google Calendarの予定詳細はDBに保存しない
## 追加メモ: Phase 2 日程確定の判断画面

作成者が日程を確定しやすいように、予定詳細と日程確定画面では候補日時をランキング表示します。

- ○が多い候補を優先する
- 同数なら△が多い候補を優先する
- ×が少ない候補を優先する
- 未回答が少ない候補を優先する
- おすすめ、未回答あり、スコア、回答率を表示する
- 確定前に確認ダイアログを出す

## 追加メモ: Phase 2 未回答者とリマインド文面

予定詳細画面では、参加者のうち未回答の人を一覧で確認できるようにします。

- 未回答者は `participants.status = invited` の参加者として扱う
- 未回答者がいる場合、回答期限と共有リンクを含むリマインド文面を生成する
- 回答期限の何時間前・何日前に声をかけるかを参加予定ごとに保存する
- 保存したリマインダー設定は予定詳細とリマインド文面に反映する
- 手動で連絡したあと、送信済みとして記録できるようにする
- 送信済み記録では前回送信時刻と記録回数を表示する
- 文面はコピーできるようにし、送信はユーザーが普段使う連絡手段で手動で行う
- LINE、メール、Discordなどへの自動送信はまだ実装しない

## 追加メモ: Phase 2 終日候補

候補日時作成画面では、候補を終日として追加できます。

- 終日候補は `candidate_dates.is_all_day` に保存する
- 終日の開始は選択日の `00:00`、終了は翌日の `00:00` として扱う
- 表示上は時刻ではなく「終日」と表示する
- 日程確定時は `plans.is_all_day` にも反映する
- Google Calendar 登録時は `dateTime` ではなく `date` 形式で予定を作成する
