## 実施順序

CLAUDE.md の推奨順とレビューの推奨順を合わせたもの。

1. **High 3（マイグレーション適用の仕組み）** — 他の RPC 化タスクの土台。まず brainstorming で手段（CLI or CI スクリプト）を決める。
2. **High 1（退会状態の正本移行）** — grill-me → 設計 doc → 実装。RLS 変更の要否をここで確定。
3. **High 2（トランザクション化）** — grill-me で RPC 一覧と退会の状態管理を固め、RPC 単位でサブエージェント実装。各タスクに実 DB テストを含める（Low 1 を吸収）。
4. **Medium 1 / 3 / 7（Google カレンダー: 冪等性 / JST 境界 / アカウント識別）** — 3 と 7 は grill-me、3 は小さいので単独で。
5. **Medium 2 / 5（Cron ページング / 同意チェックの障害時挙動）** — 独立。小〜中。
6. **Medium 6（匿名回答の仕様確定）** — ユーザーの方針決定待ち。A なら文書修正のみ。
7. **Low 2（lint 警告）** — いつでも。単独コミット。
